# イベント出展申込フォーム

イベントごとにコードを書き換えなくても、管理画面から項目・料金・ブース・メール文面を
変更できる申込フォームです。次の開催回は設定を変えるだけで立ち上げられます。

```
apply/    申込フォーム（出展者が使う）
admin/    管理画面（主催者が使う）
gas/      バックエンド（Google Apps Script）
tools/    開発用スクリプト
```

## できること

- **項目を自由に設定** — 質問文・説明書き・入力の種類（1行/複数行/選択/ラジオ/チェック/
  数値/メール/電話/郵便番号/住所/日付/URL/画像/SNSリンク）・必須の有無・文字数上限・並び順
- **ブースと料金** — ブースごとの通常価格と早割価格、満枠の切り替え
- **オプション** — コンセント使用や懇親会など任意の追加料金項目。
  **ブースの種類ごとに使える／使えないを設定できる**
- **申込中のリアルタイム料金表示** — ページ下部に合計と内訳を表示
- **自動返信メール** — 文面を管理画面で編集でき、料金の内訳と合計を差し込める
- **過去申込の呼び出し** — 本名とメールで照合し、認証コードを送って前回内容を読み込む
- **開催回のセットアップ** — スプレッドシートと画像フォルダをボタン1つで作成

## 全体の構成

```
出展者のブラウザ ──申込──▶ Apps Script ──▶ スプレッドシート / Google ドライブ
       │                        │
       └── 設定を読む ──────────┴── 設定を読む
                    │
              config.json（GitHub Pages）
                    ▲
                    └── 管理画面が Apps Script 経由で更新
```

設定は2箇所に分かれています。

| 置き場所 | 内容 | 公開範囲 |
|---|---|---|
| `apply/config.json` | 見た目、イベント情報、項目、ブース、料金、規約、メール文面 | **公開**（ブラウザが読むため） |
| Apps Script のスクリプトプロパティ | スプレッドシートID、フォルダID、管理者アドレス、パスワード、GitHubトークン | 非公開 |

`config.json` は誰でも読めます。**IDやトークンをここに書かないでください。**

## 初回セットアップ

Apps Script は**主催者のGoogleアカウント**で作成・デプロイしてください。
ウェブアプリは「デプロイした人として実行」されるため、そうすることで
スプレッドシート・画像フォルダ・送信メールがすべて主催者の所有になります。

### 1. Apps Script を作る（主催者）

1. 主催者アカウントで [script.google.com](https://script.google.com) を開き、新しいプロジェクトを作成
2. `gas/` 内の各ファイルを同名で貼り付ける（`appsscript.json` はマニフェスト）
3. 開発担当者を**編集者**として招待する（アカウントやパスワードの共有は不要）

### 2. スクリプトプロパティを設定する

プロジェクトの設定 → スクリプト プロパティに追加します。

| キー | 内容 | 必須 |
|---|---|---|
| `CONFIG_JSON_URL` | `config.json` の生URL（下記参照） | ○ |
| `ADMIN_PASSWORD` | 管理画面のパスワード | ○ |
| `DRIVE_ROOT_FOLDER_ID` | 画像を保存する親フォルダのID | ○ |
| `ADMIN_EMAIL` | 日次ダイジェストの宛先 | ○ |
| `GITHUB_TOKEN` | 管理画面から設定を保存するためのトークン | ○ |
| `GITHUB_REPO` | `owner/repo` 形式 | ○ |
| `GITHUB_BRANCH` | 既定 `main` | |
| `CONFIG_PATH` | 既定 `apply/config.json` | |
| `REPLY_TO_EMAIL` | 返信先。未設定なら `ADMIN_EMAIL` | |
| `SENDER_NAME` | 差出人の表示名 | |
| `LEGACY_SPREADSHEET_ID` | 過去データの移送元 | |

`CONFIG_JSON_URL` は GitHub Pages の URL です。
例: `https://＜ユーザー名＞.github.io/＜リポジトリ名＞/apply/config.json`

`GITHUB_TOKEN` は fine-grained personal access token で、
**このリポジトリのみ・Contents の Read and write** に絞ってください。

### 3. ウェブアプリとしてデプロイする（主催者）

デプロイ → 新しいデプロイ → 種類「ウェブアプリ」

- **次のユーザーとして実行**: 自分
- **アクセスできるユーザー**: 全員

初回実行時に Drive・Gmail・スプレッドシートの権限を承認します。
発行された `/exec` の URL を `apply/config.json` の `integration.gasUrl` に設定してください。

> **デプロイは主催者が行ってください。** 実行ユーザーがデプロイした人になるため、
> 他の人がデプロイすると、そのアカウントにファイルが作られメールもそこから送られます。

### 4. 開催回を始める

管理画面（`admin/index.html`）にパスワードでログインし、
「開催回のセットアップ」→「新規開催回を始める」を実行します。

- 今回の申込データ用スプレッドシート（ヘッダーは設定から自動生成）
- マスターDB（開催回をまたぐ照合先。過去申込の呼び出しに使う）
- 画像保存フォルダ（イベント名）
- 日次ダイジェストとメール送信のトリガー

が作られ、IDがスクリプトプロパティに保存されます。
実行前に「作成内容を確認」で何が作られるか下見できます。

**スプレッドシートやフォルダを手で作らないでください。** 必ずこのボタンから作成してください。
手で作ると作成した人の所有になります。

## 次回の開催回を立ち上げる

1. 管理画面で「イベント情報」のイベント名・開催日時を更新
2. 「ブースと料金」で価格と満枠を見直す
3. 「早割」の締切を設定
4. 保存する
5. 「新規開催回を始める」を実行

前回の申込データはマスターDBに残るので、出展者は「前回の内容を呼び出す」で
入力を省略できます。

## メール送信について

無料の Gmail アカウントでは Apps Script のメール送信は **1日100「宛先」** までです
（通数ではなく宛先数。Google Workspace なら1500）。これに合わせて次の設計にしています。

- 申込者への確認メールは**最優先で即時送信**
- 管理者への通知は1件ごとに送らず、**1日1通のダイジェスト**にまとめる
- 枠が尽きたら確認メールを送信待ちに積み、翌日のトリガーで送る
- **申込データの保存はメール送信より先に完了する**ので、送れなくても申込は失われない

管理画面の右上に本日の残量が出ます。申込開始初日など混み合う日はここで確認してください。

## 過去データの移送

以前のスプレッドシートから申込履歴を取り込めます。

1. 移送元の**閲覧権限を主催者アカウントへ付与**してもらう
2. 管理画面で移送元のスプレッドシートIDを入力
3. 「対応表を確認」で、どの列がどの項目に入るか下見する
4. 問題なければ「移送を実行」

移送元は**読み取るだけで変更しません**。同じ申込を二重に取り込むこともありません。

### 料金計算のファイルについて

`gas/pricing.gs` は `apply/config-schema.js` から自動生成しています。
Apps Script は npm のモジュールを読めないため実体を2箇所に置いていますが、
手で写すとずれるので必ず次のコマンドで同期してください。

```bash
node tools/sync-pricing.js          # 反映
node tools/sync-pricing.js --check  # ずれていないか確認
```

料金計算は「フォームの表示額」「確認メールの金額」「サーバ側の再計算」で
一致していなければなりません。`gas/pricing.gs` を直接編集しないでください。

### 設計上の要点

- **金額はサーバ側で再計算する。** 送信された金額は参考値として突合するだけです。
  ブースごとのオプション可否と上限もサーバで再判定するため、改変したリクエストで
  使えないオプションを通すことはできません。
- **ブース別のオプション可否は `booth.options[optionId]` で持つ。**
  指定がなければオプション側の `defaultAvailable` に従います。
  「指定がない＝全部使える」にはしていません。オプションを新しく追加したときに
  全ブースで意図せず有効になる事故を防ぐためです。
- **ブースを変えて使えなくなったオプションは自動で解除し、理由を画面に出す。**
  金額が理由もわからず変わるのを避けるためです。
- **スプレッドシートの列は名前で対応づける。** 位置に依存しないので、項目を後から
  増やしても既存の行がずれません。不足した列は末尾に追加されます。
- **リピーター照合は項目ID（fieldId）で行う。** `_meta` シートに列ラベルと項目IDの
  対応を保存しているため、管理者が質問文を変更しても照合が壊れません。
