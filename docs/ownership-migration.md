# GASのオーナーと実行アカウントをクライアントへ移す手順

## 目的

申込者に届く確認メールの差出人が、現在**制作者のGmailアドレス**になっている。
これを**クライアントのアドレス**に変える。あわせてGASプロジェクトのオーナー権限もクライアントへ移す。

申込の受付を止めずに実施できる。所要時間は実作業で10〜15分程度。

---

## 先に知っておくべき仕組み

### 差出人が決まる仕組み

メールは `GmailApp.sendEmail()` で送信され、**GASを実行しているアカウントから送られる**。
コード側で差出人アドレスを指定することはできない。つまり差出人を変えるには、
**実行アカウントそのものを切り替える**しかない。

### オーナー権限と実行アカウントは別物

ウェブアプリの「次のユーザーとして実行：自分」の「自分」は、**そのデプロイを行ったアカウント**に紐づく。

| 操作 | 差出人 | 稼働への影響 |
|---|---|---|
| クライアントを編集者として追加 | 変わらない | なし |
| オーナー権限を譲渡 | **変わらない** | なし |
| **クライアントが再デプロイ** | **クライアントに変わる** | 切替の瞬間のみ |

**オーナーを移しただけでは差出人は変わらない。** 逆に、編集者でもデプロイはできるので、
この2つは独立して進められる。本手順では、リスクの小さい順に検証しながら進める。

### 差出人が変わっても受信者への影響は小さい

`sendConfirmationEmail()` は送信オプションに表示名と返信先を渡している。

- **表示名**：config の `adminSenderName`＝「ぶち癒しフェスタin小田原事務局」のまま。受信箱での見え方はほぼ変わらない
- **返信先**：config の `replyToEmail`＝`odawara.buchi@gmail.com` のまま。**返信は今までどおり事務局に届く**

変わるのは実際の送信元アドレスと、1日100通の送信上限を消費するアカウントだけ。

## ステップ1：事前準備（影響ゼロ・いつでも可）

1. **バックアップ**：GASエディタで「ファイル → コピーを作成」、またはコード全文をテキストで保存
2. **GASプロジェクト**にクライアントのGoogleアカウントを**編集者**として追加
3. **現行スプレッドシート**にクライアントを**編集者**として追加
   - 切替後はクライアントの権限で書き込むため必須。忘れると申込が保存されない
4. **写真フォルダ**（クライアント所有）に、制作者が編集者として残っていることを確認
   - 切り戻したときに制作者の権限で書き込めるようにするため

---

## ステップ2：実行アカウントの切り替え（申込の少ない時間帯に）

ここが本番の作業。**クライアントのアカウントで**操作する。

1. GASプロジェクトを開き、「**デプロイ → デプロイを管理 → ✏️（編集） → バージョン：新バージョン → デプロイ**」
   - ⚠️ 「**新しいデプロイ**」は選ばない（URLが変わり、申込が届かなくなる）
   - 「アクセスできるユーザー：**全員**」「次のユーザーとして実行：**自分**」が維持されているか確認
2. 初回は**OAuth同意画面**が表示される。「このアプリは確認されていません」という警告が出た場合は、
   「**詳細**」→「**（プロジェクト名）に移動**」から承認する
3. **直後にテスト申込を1件送信し、以下を確認**
   - ✅ **確認メールの差出人がクライアントのアドレスになっている**（本命）
   - ✅ 表示名が「ぶち癒しフェスタin小田原事務局」のまま、返信先が `odawara.buchi@gmail.com`
   - ✅ スプレッドシートに行が追加される
   - ✅ 写真がDriveに保存され、リンクが開ける
   - ✅ 管理者通知メールが届く
4. 確認できたら、テスト行と画像を削除

うまくいかない場合は、Apps Script の「**実行数**」画面でエラー内容を確認する。
権限エラーなら、ステップ1-3（スプレッドシートの編集権限）が抜けている可能性が高い。

---

## ステップ3：オーナー権限の譲渡（稼働への影響なし）

ステップ2が問題なく動いていることを確認してから実施する。

1. GASプロジェクトの共有画面で、クライアントを**オーナーに指定**して譲渡
2. クライアント側で譲渡を**承諾**してもらう
3. **制作者が編集者として残っていることを必ず確認**
   - 完全に権限が外れると、保守も切り戻しもできなくなる

この順序なら、いちばんリスクのある実行アカウント切替を、まだオーナー権限が手元にある状態で検証できる。

---

## 切り戻し

| 戻したいもの | 方法 |
|---|---|
| 差出人を制作者に戻す | **制作者のアカウントで**同じ手順（デプロイを管理 → 新バージョン → デプロイ）を実行。URLは変わらないので config.json の変更は不要 |
| オーナー権限 | 再度譲渡し直す |
| 最悪の場合 | ステップ1のバックアップから別プロジェクトを復元。ただし**URLが変わる**ため、管理画面の「システム設定」で `gasUrl` の更新が必要 |

---

## 次回開催分の準備（会期終了後）

今回開催分は現行スプレッドシートをそのまま使い、次回開催分からクライアント所有のシートで集計する。

1. **次回用スプレッドシートをクライアント所有で作成**
   - 上記の移行が済んでいれば、管理画面の「✨ スプレッドシートを新規作成」で作ると
     自動的にクライアント所有になる（`docs/gas-setup.md` の③を追加済みの場合）
   - 追加していない場合は、クライアントのアカウントでGoogleドライブから新規作成し、URLをコピー
2. GASエディタで `setupSpreadsheet()` を実行してヘッダー行を用意（省略可。初回申込時に自動生成される）
3. 管理画面「📅 開催回とデータの保存先」で「**＋ 新しい開催回を追加**」
   - 開催回の名前とスプレッドシートURLを設定
   - ⚠️ **この時点では「受付中」に切り替えない**（今回分の申込が新しいシートに入ってしまう）
4. 次回の受付開始時に「受付中」を切り替えて保存
   - 「**すぐに反映されます**」と表示されれば完了
   - 「最大30分」と表示された場合は、GASエディタで `clearConfigCache()` を手動実行
     （`docs/gas-setup.md` の①が未対応の状態）
5. テスト申込を1件送信し、新しいスプレッドシートに入ることを確認して削除

## 今回開催分のデータの引き渡し

今回の申込データは制作者所有のスプレッドシートに残る。会期終了後、次のいずれかで引き渡す。

- スプレッドシートをクライアントへ共有する
- 「ファイル → コピーを作成」でクライアントのドライブに複製する
- スプレッドシート自体のオーナー権限を譲渡する（GASは次回分の新シートを見ているため影響なし）
