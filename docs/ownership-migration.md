# スプレッドシート・GASをクライアントのアカウントへ移行する手順

## 方針

**今回開催分（第1回）は現在のスプレッドシートをそのまま使い、次回開催分からクライアント所有のシートで集計する。**

この方針により、申込を受け付けている最中に移行作業を行う必要がありません。
会期が終わってから、落ち着いて切り替えられます。

| 対象 | 現在 | 移行後 |
|---|---|---|
| 申込データのスプレッドシート | 制作者所有（今回分） | クライアント所有（次回分から新規作成） |
| Apps Script（GAS） | 制作者所有 | クライアント所有 |
| 写真フォルダ（Drive） | クライアント所有（移行済み） | 変更なし |
| Cloudflare Worker / GitHub | 制作者所有 | 変更なし |

---

## 事前に確認すること

### 1. 写真フォルダの権限（今すぐ）

写真フォルダは既にクライアント所有へ移っています。**現在GASを実行しているアカウント（制作者）に、
そのフォルダの編集権限が残っているか**を確認してください。

権限が外れていると、`saveProfileImage()` が失敗しても例外が握りつぶされるため、
**申込自体は成功するのに写真URLだけ空になり、エラーに気づけません。**

> 確認方法：申込フォームからテスト送信し、スプレッドシートの「プロフィール写真」列にURLが入るか見る。

### 2. GASの種類（フェーズ1の前に）

Apps Script が**スタンドアロン**か、スプレッドシートに**コンテナバインド**かで手順が変わります。

- スプレッドシートを開き「**拡張機能 → Apps Script**」で同じコードが開く → **コンテナバインド**
  → スプレッドシートの所有者を移すと、GASも一緒に移ります
- 開かない（別プロジェクトになっている） → **スタンドアロン**
  → スプレッドシートとGASを別々に移行します

## フェーズ1：GASのオーナー移行（今回の会期終了後）

1. script.google.com で対象プロジェクトを開く
2. 「共有」から**クライアントのGoogleアカウントを編集者として追加**
3. 同じ共有画面で、クライアントを**オーナーに指定**して権限を譲渡
4. クライアント側で譲渡を**承諾**してもらう
5. **クライアントのアカウントで**「デプロイ → デプロイを管理 → ✏️ → 新バージョン → デプロイ」を実行
   - **URLは変わりません**。config.json の変更は不要です
   - 「新しいデプロイ」は選ばないでください（URLが変わり、申込が届かなくなります）
6. 制作者は**編集者として残る**（保守のため）

### 移行すると変わること（事前にクライアントへ周知が必要）

- **確認メールの送信元アドレスがクライアントのGmailになります**
  （`GmailApp.sendEmail` はGASを実行しているアカウントから送信されるため）
- 送信者名（`adminSenderName`）と返信先（`replyToEmail`）は config.json の設定のままなので変わりません
- 管理者通知メールの宛先（`adminEmail`）も変わりません
- Gmailの送信上限（無料アカウントは1日100通）は、クライアント側のクォータを消費します
- 写真フォルダへの書き込みは、**新しい実行アカウント（クライアント）の権限**で行われます

### 移行後の動作確認

1. GASエディタで `testDoPost()` を実行し、ログにエラーが出ないこと
2. 申込フォームからテスト申込を1件送信し、次を確認
   - スプレッドシートに行が追加される
   - 写真がDriveに保存され、リンクが開ける
   - **確認メールの送信元がクライアントのアドレスになっている**
   - 管理者通知メールが届く
3. テスト行と画像を削除

---

## フェーズ2：次回開催分の準備

1. **次回用スプレッドシートをクライアント所有で作成**
   - GAS移行後なら、管理画面の「✨ スプレッドシートを新規作成」で作れば自動的にクライアント所有になります
     （`docs/gas-setup.md` の③を追加済みの場合）
   - 追加していない場合は、クライアントのアカウントでGoogleドライブから新規作成し、URLをコピー
2. GASエディタで `setupSpreadsheet()` を実行してヘッダー行を用意（省略可。初回申込時に自動生成されます）
3. 管理画面「📅 開催回とデータの保存先」で「**＋ 新しい開催回を追加**」
   - 開催回の名前（例：第2回（2027年3月1日））とスプレッドシートのURLを設定
   - **この時点では「受付中」に切り替えないでください**（今回分の申込が新しいシートに入ってしまいます）
4. そのまま「💾 Webに保存」

---

## フェーズ3：次回の受付開始

1. 管理画面で「**いま受付中の開催回**」を次回に切り替える
2. 「💾 Webに保存」
   - 「**すぐに反映されます**」と表示されれば完了
   - 「最大30分」と表示された場合は、GASエディタで `clearConfigCache()` を手動実行してください
     （`docs/gas-setup.md` の①が未対応の状態です）
3. テスト申込を1件送信し、**新しいスプレッドシート**に入ることを確認 → テスト行と画像を削除
4. 受付を開始

---

## 切り戻し

いずれの段階でも、オーナー権限を再度譲渡し直すことで元に戻せます。
**デプロイURLは所有者が変わっても変化しない**ため、config.json やフォーム側の変更は不要です。

開催回の切り替えを戻す場合は、管理画面で「受付中」を元の回に戻して保存するだけです。
過去の開催回の設定（スプレッドシートURL）は削除されずに残っています。

---

## 今回開催分のデータの引き渡し

今回の申込データは制作者所有のスプレッドシートに残ります。会期終了後、次のいずれかで引き渡してください。

- スプレッドシートをクライアントへ共有する（閲覧または編集）
- 「ファイル → コピーを作成」でクライアントのドライブに複製する
- スプレッドシート自体のオーナー権限を譲渡する（GASは新シートを見ているため、影響ありません）
