# 出展者データベース仕様

スプレッドシート: `1QjOHkZRXZOJF7e6pslNPO2S_rnnHXaUxhY_LJrH9D6M`

開催回をまたいで出展者情報を蓄積し、次回以降の申込で「前回データの呼び出し」に使います。
シートは3つ。**1行目がヘッダー、2行目以降がデータ**です。

> 列は追加のみ可、**並び替え・削除はしないでください**（バックエンドが列名で参照します）。
> 手作業で直すのは「座席番号・入金確認・入金日・ステータス・スタッフメモ」の5列を想定しています。

---

## 1. `applications` — 申込明細（1申込＝1行・追記のみ）

すべての開催回の申込がここに貯まります。

| 列名 | 内容 |
|---|---|
| 申込ID | `第1回-0001` のように、開催回＋連番で自動採番 |
| 開催回ID | 開催回の識別子（例: `第1回`）。管理画面の「開催回」がそのまま入ります |
| 開催回 | 表示用（例: `第1回`） |
| イベント名 | 例: `第1回ぶち癒しフェスタin小田原` |
| 出展者ID | `exhibitors` シートへの紐付け（例: `EX0007`） |
| 申込日時 | `yyyy/MM/dd HH:mm:ss` |
| 氏名 / フリガナ / メールアドレス / 電話番号 / 郵便番号 / 住所 | 申込者情報 |
| 出展カテゴリ / 出展名 / 出展ブース | 出展情報 |
| 出展メニュー名 / 自己紹介 | フォームのカスタム質問の回答 |
| 持ち込み物品 | ボディブース等の申告 |
| SNS | `Instagram: https://...` の形式（複数行） |
| 写真掲載可否 / プロフィール写真 | 写真のSNS掲載可否と Drive のURL<br>写真は「親フォルダ / 開催回」の中に `氏名_出展名.jpg` で保存されます |
| コンセント | `あり` / `なし` |
| 懇親会出欠 / 懇親会人数 / 二次会出欠 / 二次会人数 | |
| 協会会員 | `はい` / `いいえ` |
| 景品提供 / 景品内容 | スタンプラリー用 |
| 備考・質問 | 申込者からの記入 |
| **座席番号** | 当日の配置（手入力） |
| 合計金額 | 自動計算された出展料 |
| **入金確認 / 入金日** | 事務局が手入力 |
| **ステータス** | `申込` / `入金済` / `キャンセル` など（手入力可） |
| **スタッフメモ** | 対応履歴（手入力） |
| LINEユーザーID / LINE表示名 | LIFF連携時のみ |
| 登録元 | `form`（フォーム送信） / `migration`（受付シートから取り込み） |
| 登録日時 | DBへ書き込まれた日時 |

**重複しない仕組み**: 「開催回ID＋メールアドレス＋申込日時」が同じ行は登録されません。
そのため取り込み処理を何度実行しても増えません。

## 2. `exhibitors` — 出展者マスタ（同じ人は1行）

メールアドレス（小文字化・前後空白除去）をキーに名寄せします。
メールが無い招待枠などは「氏名＋出展名」がキーになります。

| 列名 | 内容 |
|---|---|
| 出展者ID | `EX0001` 形式 |
| メールキー | 名寄せキー（小文字化したメール、または `name:氏名/出展名`） |
| 氏名 / フリガナ / メールアドレス / 電話番号 / 郵便番号 / 住所 | 最新の連絡先 |
| 最新出展名 / 最新出展カテゴリ / 最新出展メニュー名 / 最新自己紹介 / 最新SNS / 最新プロフィール写真 | 直近の申込内容 |
| 出展回数 | 申込が入るたびに +1 |
| 初回申込日時 / 最終申込日時 | |
| 最終開催回 | 例: `第2回` |
| スタッフメモ | 手入力（上書きされません） |

> 更新時、**空の値では上書きしません**。前回入っていた情報は残ります。

### 使い方の例

- 出展回数が2以上 → リピーター
- 最終開催回が `第1回` のまま → 今回まだ申込が無い方（次回の声かけリスト）

---

## 3. `events` — 開催回マスタ

| 列名 | 内容 |
|---|---|
| 開催回ID | `第1回` など |
| 開催回 / イベント名 / 開催日時 / 会場 | config.json の `event` から自動記録 |
| 受付スプレッドシートID | その回の受付スプシ |
| 申込件数 | `applications` から自動集計 |
| 登録日時 | 最終更新日時 |

---

## 前回データ呼び出しの流れ

1. 出展者がフォームで「前回内容を呼び出す」→ 氏名とメールを入力
2. バックエンドが `applications` を検索し、一致すれば4桁の認証コードをメール送信
3. コードを入力すると、過去の申込が新しい順に一覧表示される
4. 選ぶと、住所・出展名・メニュー・自己紹介・SNS・前回写真などが自動入力される

> 検索は `applications` を優先し、まだDBが空の場合は受付スプシを直接検索します。
> この機能は config.json の `features.repeaterSearch` が `true` のときだけ表示されます。
